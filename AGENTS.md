# AGENTS.md

Конфиг-репозиторий OpenClaw: здесь лежит конфигурация Telegram-бота, который живёт на
VDS-сервере (v815382.hosted-by-vdsina.com). Самого OpenClaw здесь нет — только `openclaw.json`,
рабочая область бота и служебные файлы.

## Главное, что нужно знать

- **main авто-деплоится на прод.** Cron на сервере каждые 5 минут выполняет:
  `git pull` → `openclaw config validate` → restart gateway → health-check.
  Любое изменение `openclaw.json` в main через несколько минут применится к живому боту.
  Некорректный конфиг откатывается автоматически, но лучше самому валидировать до пуша.
- **Репозиторий публичный — секретов здесь нет и не будет.** Ключи и токены живут на
  сервере (в `/root/.openclaw/secrets.env` и служебных каталогах) и подключаются через
  SecretRef (`source: env`). В конфиге можно только ссылаться на env-переменную и добавить
  её имя в `secrets.providers.env.allowlist`. Не вписывай значения ключей в `openclaw.json`
  и не добавляй в коммиты никакие файлы с секретами.
- **Сервер сам коммитит свои правки** («local auto-commit before deploy …»). Если между
  твоим пуллом и пушем появились серверные коммиты — не перезаписывай их, сделай rebase/merge.

## Структура

| Путь | Что это |
|---|---|
| `openclaw.json` | основной конфиг: модели, агенты, gateway, каналы, skills, mcp, commands, tools, plugins |
| `workspace/` | рабочая область бота: его личность и память; трекаются только `*.md`, `memory/`, `skills/` |
| `devices/`, `media/`, `credentials/` | runtime-данные сервера (спаренные устройства, входящие медиа, служебные секреты) — в git не включаются |
| `npm/projects/` | локальные npm-проекты для плагинов (например, `openclaw-brave-plugin-…`) |
| `README.md` | схема деплоя и восстановление на новом сервере |

## Правки конфига

- Перед коммитом проверяй валидность: `openclaw config validate` или хотя бы
  `python3 -m json.tool openclaw.json`.
- **Не используй `plugins.allow`** — он отключает встроенные плагины (уже дважды
  обжигались, было revert). Плагин включается через `plugins.entries.<name>.enabled = true`.
- Секреты — только через `{"source": "env", "provider": "env", "id": "ИМЯ_ПЕРЕМЕННОЙ"}`.
- Не трогай `meta.*` и `wizard.*` — сервер обновляет их сам, конфликты только помешают.
- Знай семантику ограничений: `tools.deny` — общие запреты для бота, `tools.toolsBySender` —
  точечные разрешения для конкретных отправителей, `commands.ownerAllowFrom` — кто может
  слать команды боту.

## workspace/

- `workspace/AGENTS.md` — инструкции **для самого бота**, не для кодинг-агентов. Это
  «личность» бота; не редактируй его без явного запроса.
- Остальное состояние бота (state, logs, sqlite, identity) в `.gitignore` и не должно
  попадать в коммиты.

## Секреты

- Нельзя пушить секреты в этот репозиторий: он публичный, и любой коммит с секретом —
  это утечка.
- Секреты (ключи API, токены, файлы с паролями) живут только на сервере и в git не
  попадают.
- Если секрет всё же попал в историю — он считается скомпрометированным: его нужно
  ротировать на сервере, а файл исключить из трекинга и добавить в `.gitignore`.
